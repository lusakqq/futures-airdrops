# Бот №2: быстрый шорт на Bitget в момент открытия фьючерса

Бот ждёт, когда на Bitget откроется фьючерс USDT-M нужной монеты, и сразу открывает
рыночный шорт на заданную сумму и плечо. Стоп-лосс прикрепляется **внутри того же ордера**
(Bitget называет это «preset stop loss»), то есть позиция ни секунды не висит без стопа.
Если биржа откажет именно из-за цены стопа (цена успела улететь), бот откроет позицию без него
и сразу поставит стоп отдельно от реальной цены входа. Если и это не выйдет, бот закроет позицию.

## 1. Установка (один раз)

1. Установите Python 3.10 или новее с https://www.python.org/downloads/
   (в установщике Windows поставьте галочку **Add Python to PATH**).
2. Скачайте папку `3_bot_futures` к себе на компьютер.
3. Откройте в этой папке командную строку (в Проводнике в адресной строке напишите `cmd` и Enter).
4. Выполните:
   ```
   pip install -r requirements.txt
   ```
5. Скопируйте файл `.env.example` в `.env` и откройте `.env` Блокнотом.

## 2. Как получить API-ключи Bitget

**Сначала демо-ключи (виртуальные деньги, ничем не рискуете):**
1. Войдите на bitget.com, вверху переключитесь в **Демо-торговлю** (Demo trading).
2. Откройте профиль → **API-ключи** (API Management) → **Создать API-ключ** → «Ключ, созданный системой».
3. Придумайте **Passphrase** (пароль ключа) и запишите его, его потом не покажут.
4. Права: только **Фьючерсы → Ордера и Позиции (чтение и запись)**. **Вывод (Withdraw) и Перевод НЕ включайте.**
5. Bitget покажет **API Key** и **Secret Key**. Скопируйте их в `.env`:
   ```
   BITGET_API_KEY=...
   BITGET_API_SECRET=...
   BITGET_API_PASSPHRASE=...
   MODE=demo
   ```

**Потом настоящие ключи (только когда всё проверили в demo):**
то же самое, но в обычном (не демо) режиме. Обязательно:
- права только на торговлю фьючерсами, **без вывода средств**;
- если есть постоянный IP-адрес, впишите его в **IP whitelist** (привязка к IP), тогда украденный ключ бесполезен;
- никому не показывайте файл `.env` и не загружайте его в интернет.

Перед реальной торговлей переведите USDT со спотового счёта на **фьючерсный счёт USDT-M**
(Активы → Перевод).

## 3. Запуск

```
python short_bot.py DOGS/USDT
```
или просто `python short_bot.py`, и бот спросит монету.

Порядок проверки:
1. `MODE=dry`: ключи не нужны, бот ничего не отправляет и только печатает ордер, который отправил бы.
   Проверьте на любой уже торгующейся монете, например `BTC/USDT`: бот сразу увидит, что торги открыты.
2. `MODE=demo` на `BTC/USDT`: позиция откроется на демо-счёте. Убедитесь в приложении, что у позиции
   виден стоп-лосс, и закройте её вручную. Новых листингов на демо-счёте обычно нет.
3. `MODE=live`: бот попросит ввести `YES`. Запускайте заранее, за 5-10 минут до объявленного старта фьючерсов.

Остановить бота: `Ctrl+C`.

## 4. Настройки в `.env`

| Параметр | Что значит | По умолчанию |
|---|---|---|
| `MARGIN_USDT` | сколько **своих** денег идёт в сделку | 10 |
| `LEVERAGE` | плечо, бот разрешает 1-10 | 3 |
| `STOP_LOSS_PCT` | стоп выше входа на N % | 15 |
| `TAKE_PROFIT_PCT` | тейк ниже входа на N %, 0 = не ставить | 0 |
| `POLL_SECONDS` | пауза между проверками | 0.2 |

Пример: `MARGIN_USDT=10`, `LEVERAGE=3` → позиция примерно на $30.
Стоп +15% при плече 3х = потеря около $4.5 из $10 маржи плюс комиссии и проскальзывание.

Бот не даст поставить стоп ближе к ликвидации, чем 80% пути до неё
(при 3х ликвидация примерно на +33%, значит стоп должен быть меньше ~26%).

## 5. Что важно знать

- Стоп-лосс это рыночная заявка, которая срабатывает при достижении цены. В резком сквизе
  её исполнят хуже, чем на 15% (проскальзывание). Изолированная маржа ограничивает потерю суммой этой сделки.
- Фьючерсы на Bitget часто открываются **позже** спота или вообще не открываются для мелких монет.
  Смотрите точное время в официальном анонсе Bitget.
- В первые минуты у новых контрактов бывает очень большой funding (плата за удержание позиции)
  и ограничено максимальное плечо.
- Бот проверен на синтаксис и в режиме dry на имитации биржи. С реальной биржей он не тестировался
  (у меня нет ваших ключей), поэтому обязательно пройдите шаги dry → demo перед live.
